# DicomStudyCount

Find duplicated DICOM files and badly organized folders straight from Windows Explorer.

Right-click a folder and choose **Count DICOM studies**: every folder and subfolder gets a summary in
Explorer's **Comments** column (studies, date, series) together with warnings for the problems found:
studies split across folders, duplicated images, incomplete series and copies in other locations.
**Show DICOM tree** opens the whole folder tree with one color per study.

## Features

- **One header read per file.** Only the DICOM header is read (up to InstanceNumber, tag 0020,0013),
  never the pixel data. Supports Explicit/Implicit VR Little Endian, Explicit VR Big Endian, Deflated
  and "raw" files without preamble. Non-DICOM files are ignored. Parallel reading.
- **Comments column in Explorer**, written in every folder:

  | Folder contents | Comment |
  |---|---|
  | several studies | `4 DICOM studies` |
  | one study | `[MR-hwmA0] 02/Jun/2025 - 4 series` |
  | one study, one series | `[MR-hwmA0] 02/Jun/2025 - 007.cine_retro_4ch (25 of 25)` *(DICOM files of all files)* |
  | files, but no DICOM | `No DICOMs.` |
  | no files at all (subfolders included) | `---` |

  `[MR-hwmA0]` is the study tag: the study's main image modality plus 5 case-sensitive characters from
  a hash of the StudyInstanceUID, so the same study always has the same tag in every folder and run.
- **Problems** (appended to the comments with `⚠`, and listed in the tree's *Problems* window):
  - **Study split across folders**: the same study in more than one separate folder.
  - **Duplicated files**: same StudyInstanceUID and SOPInstanceUID, then same size and SHA-256, then a
    full byte-by-byte comparison, so a hash collision can never produce a false duplicate. Copies with
    different contents are reported apart.
  - **Incomplete series**: a folder missing InstanceNumbers of a series, compared with the whole tree
    (e.g. a partial copy of a series that is complete elsewhere).
  - **Copies in other counted locations**: every count keeps an index of its files (path, size, date
    and time, study and image UIDs); copies found in other counted folders or disks are confirmed with
    the same byte-by-byte comparison. Entries of deleted or replaced files are dropped from the index.
- **DICOM tree window**: the folder tree with the number of files (recursive), the comment of every
  folder, one pastel color per study, *Expand to studies* (expands until studies separate), live
  updates while counting and when files or folders change, and the *Problems* window.
- **No window while counting**: folders show `Counting StudyUIDs...` and are updated one by one as
  they are finished; the Comments column is added to open Explorer windows and fitted to the text.
- **Background watcher**: adds the Comments column (last, fitted to the text) whenever you browse a
  folder that has comments written by this tool.

## Requirements

- Windows 10 or 11.
- Windows PowerShell 5.1 (included in Windows). No other dependencies: the DICOM reader is C# code
  embedded in the script and compiled on the fly.
- No administrator rights: everything is installed for the current user (`HKCU`).

## Installation

1. Copy `Count-DicomStudies.ps1` to a permanent folder, for example
   `C:\Users\<you>\Tools\DicomStudyCount\`. The context menu points to that path, so run `-Install`
   again if you move it.
2. If the file was downloaded, unblock it:
   ```powershell
   Unblock-File .\Count-DicomStudies.ps1
   ```
3. Install the context menu and the background watcher:
   ```powershell
   powershell -NoProfile -ExecutionPolicy Bypass -File .\Count-DicomStudies.ps1 -Install
   ```
4. Recommended: hide protected operating system files (Explorer > *Options* > *View* >
   *Hide protected operating system files*), so the `desktop.ini` files are not shown.

On Windows 11 the menu entries are under **Show more options** (or Shift+F10).

To remove the context menu and the watcher:
```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\Count-DicomStudies.ps1 -Uninstall
```

## Usage

**From Explorer** (right-click a folder, or the background of an open folder):

- **Count DICOM studies**: counts the folder and writes the comments of the whole tree.
- **Show DICOM tree**: opens the tree window. It reads the comments only; use its
  *Count DICOM studies* button (or the context menu) to count.

**From PowerShell:**

```powershell
.\Count-DicomStudies.ps1 D:\Patients                     # summary and problems in the console
.\Count-DicomStudies.ps1 D:\Patients -Detail             # plus a table of studies
.\Count-DicomStudies.ps1 D:\Patients -Csv C:\temp\x.csv  # export the studies (';' separated)
.\Count-DicomStudies.ps1 D:\Patients -WriteComments      # what "Count DICOM studies" does
.\Count-DicomStudies.ps1 D:\Patients -ShowTree           # what "Show DICOM tree" does
.\Count-DicomStudies.ps1 D:\Patients -ClearComments      # remove the comments written by the tool
```

## What it writes, and where

| What | Where | Undo |
|---|---|---|
| Folder comments | a hidden `desktop.ini` in each folder with DICOM, and the folder's Read-only attribute (needed by Explorer to read it) | `-ClearComments` removes only what the tool wrote and restores the attribute |
| Problems report | `%LOCALAPPDATA%\DicomStudyCount\reports\` (one JSON per counted folder) | delete the folder |
| Index of counted locations | `%LOCALAPPDATA%\DicomStudyCount\index\` (one TSV per counted folder) | delete the folder |
| Context menu and watcher | `HKCU\Software\Classes\Directory\...` and `HKCU\...\Run` | `-Uninstall` |

The tool never modifies, moves or deletes DICOM files. The reports and the index contain file paths
and DICOM UIDs, but no patient names or IDs read from the files (folder names, of course, may carry
patient information), and they stay on the local machine.

## Notes and limitations

- Comments are a snapshot of the last count: count again after moving or copying data.
- Explorer only refreshes after ~0.6 s without change notifications; the tool pauses 1 s after
  marking folders as *Counting* so that state is visible.
- Explorer cannot color cells or rows (color emoji are drawn in gray), hence the study tags; colors
  are only available in the tree window, where they are assigned in tree order so consecutive studies
  get clearly different hues.
- Explorer's sorting and search are case-insensitive, while study tags are case-sensitive.
- Incomplete series are judged on the range of InstanceNumbers seen (min..max): gaps before the lowest
  number seen cannot be detected. Non-image series such as Siemens *PhoenixZIPReport* often have gaps.
- Copies with re-generated UIDs (re-exported or anonymized studies) are not detected as duplicates:
  that would need a hash of the pixel data, i.e. reading whole files.
- **Quarantine** of identical duplicates (moving copies to a `_DicomQuarantine` folder, with a log to
  undo it, `-RestoreQuarantine`) is implemented but its interface is disabled
  (`$script:quarantineEnabled = $false` in `Show-DicomTree`) and it has not been tested end to end.
